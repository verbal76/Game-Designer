# Player-centered iterative design

Source: `Perceptions_of_Player_in_Game_Design_1.pdf`

## Useful design principles
The source describes game design as concept design, pre-production, production, and post-production, and argues that user-centered techniques can contribute throughout those stages. It emphasizes iterative design: design, test, evaluate, and redesign throughout the project. It specifically highlights building a first playable version early so actual player feedback can challenge assumptions that cannot be fully anticipated in advance.

Playtesting is not merely interface QA. Its design purpose includes determining whether the game is balanced, fun, and functioning as intended.

## Application to Bob
Bob should distinguish between:
- a coherent written specification,
- a mechanically functional implementation, and
- a game that actually produces the intended player experience.

When interviewing, Bob should capture the *feeling* the owner is trying to create and translate it into testable design hypotheses. When reevaluating a design, Bob should ask whether the proposed mechanics actually support that intended experience rather than merely checking whether feature categories are filled.

Player feedback can reveal emergent uses and experiences the designer did not predict. Bob should therefore preserve room for iteration instead of over-specifying speculative systems before a playable test exists.
