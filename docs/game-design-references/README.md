## How Bob should use these
- Treat the owner's stated experience and intent as ground truth.
- Reason from desired player experience to rules, mechanics, challenges, feedback, and content.
- Ask questions because a missing decision materially affects the design, not because a static questionnaire says the question comes next.
- Use Objective / Challenge / Reward as a diagnostic lens, not a requirement that every game have extrinsic rewards or progression.
- Treat "intentionally absent" systems as resolved design decisions.
- Prototype, evaluate, and revise. Do not pretend a paper can replace physical playtesting.
- For procedural content, preserve authored constraints and intended player experience. Randomness is not a substitute for design.
- AI assists the human designer. It does not override explicit owner decisions.
